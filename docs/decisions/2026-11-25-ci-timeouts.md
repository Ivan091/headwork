# 2026-11-25: CI job timeouts and atomic releases

Every job in `gate.yml` and `release.yml` now has `timeout-minutes` (gate and build 30, publish 10; measured runs take 4 to 10 minutes, and a macOS job that waited 15 minutes for a runner is cancelled by GitHub itself and never reaches the timeout, which only ends hung jobs), and the publish step tries up to three times, creating the release or, when it exists, uploading with `gh release upload --clobber`, and checks after each try that it holds every staged asset, because two releases failed on a GitHub HTTP 500. A release is still published only when both the Windows and the macOS build pass: `headwork update` fails deterministically on a release that lacks its platform's asset (`has no <asset>`, `ops/update.rs`) and would raise `update-failed` on that machine, so publishing one binary would trade a missing release for a broken one; a failed macOS runner leaves no release and the next merge builds the newest commit.
