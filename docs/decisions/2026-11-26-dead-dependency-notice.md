# 2026-11-26: a queued task whose dependency is gone says so

A dependency still counts only when merged (`Dependency::Merged`); that meaning did not change. A dependency that can never merge is now `Dependency::Gone`: the task is `dropped` or `failed`, or it is `closing` or `closed` with no open pull request, none merged. Its dependent's start is refused with its own reason (`Refusal::DependencyGone`, "the task it depends on is gone ... drop this task or re-point it") instead of "not merged yet", `board` adds "waits on <task> (<state>), which never merges" to the queued task's row and `status` to its line and JSON (`dead_dependency`). The tick stage `dead_dependencies`, after the queue stage, raises the standing finding `dead-dependency` per dependent and dependency (resolved when either is dropped, re-pointed or merged) and sends one notification, repeated after 24 hours while it still stands (event `dead-dependency-told`). A dependency closed with an open pull request stays `Waiting`, since the user may still merge it. The orchestrator drops the dependent or spawns it again with another `--after`. The queue's repeated refusal of this case is logged only when it differs from the task's newest `refused` event (`last_refusal_is`): the live log had 473 identical "not merged yet" refusals for this case. Other refusals still log on every try.
